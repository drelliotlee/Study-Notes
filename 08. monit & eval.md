# Evaluation
- options for evaluation
	- automatic metrics (cheap but not helpful)
		- ROGUE - basically fancy way of measuring how many same words occur in prompt and response
		- Perplexity - put partial text into your model, perplexity measures how good it is at predicting the next word. ignores measuring if "good" at task
	- human evaluation (helpful but expensive)
		- humans can disagree/are subjective
			- dont rate 1-5, ask if A or B is better
		- human evaluation is slow and expensive
	- benchmarks
		- benchmark overfitting is a real problem
	- user feedback
		- thumbs down
		- regeneration requests
		- session abandonment
- why is evaluation hard? multi-dimensional metric
	- fluent but wrong (overconfidence, hallucinations)
	- accurate, but wrong presentation (too long, off-tone w brand)
	- accurate, but unsafe
	- accurate but operationally unhealthy (responses too slow)
	- accurate in aggregate, but inaccurate on specific area
- Goodhart's Law
	- any metric that becomes a target slowly becomes a bad target
		- overfitting for benchmarks
		- appeasing to human experts

# Data drift
- covariate
	- the input X's changed
	- ex. trained on product reviews, customers writing longer reviews now
- label drift
	- the output Y's changed
	- ex. a disesase which used to be rare is now common
- concept drift
	- the relationship btw X & Y changed
	- ex. detecting toxic language, but culture and slang evolved.
- model-induced drift
	- outputs of model affect future inputs
	- ex. recommending movies changes how users choose future movies
- how to detect data drift before quality degrades
	- input drift
		- track input length
		- track input vocabulary distribution
		- track input embeddings
	- output drift
		- track refusal rate (due to safety guardrails)
		- track output length
		- track n-gram repetition
		- run outputs throguh classifiers for harmful content, profanity, policy violations
		- run outputs through sentiment classifiers for tone check
