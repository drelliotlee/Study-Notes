- Key parameters
	- T = tokens/context length (2048)
	- E = dim of embedding space (12288)
	- D = dim of inner space of Q, K, & V (128)
	- L = # of layers / # of attention heads (96)
		- DxL = E ← common choice

- Intuition behind Q and K
	- X@Q = where should I look to be disambiguated?  
	- X@K = where should others look for me to disambiguate themself?  
	- (lead@Q) @ (pipe@K)  = high magnitude
		- lead searches for other words to disambiguate itself, pipe responds to its search  
	- (pipe@Q) @ (lead@K) = low magnitude
		- pipe not an ambiguous word, lead does not enrich its meaning much.
- Computation cost
	- the @ in `Q@K^T` is a matrix of size ExE, largest memory computation

# Implementation Issues
- Batch size `DataLoader(batch_size=32)` 
	- how many sentences per batch
	- smaller → converge to better final states, but slower
	- larger →faster, but can converge to worse final states
- Max_length `tokenizer(batch, padding=True, truncation=True, max_length=512)`
	- pretty much always going to have padding and truncation to be true, or else nothing will math. (unless we dealt with it elsewhere in the pipeline)
	- smaller max_length → faster compute / less memory, but truncate information
	- larger max_length → slower
	- always remember to use `model(...,attention_mask=attention_mask)` to tell the training, after calculating `Q@K^T`, set attention to padding tokens to -∞
	- 512/1024 is standard choices, or 95% percentile of longest document
	- in inference, use dynamic batching (handled by vLLM internally)

		- predict hard label w highest prob only if above threshold, else return "i don't know" label

	- final embedding tensor
		- semantic search = find other relevant documents via nearby CLS vectors
		- clustering of documents
		- few-shot classification w KNN
			- even with no training/backprop/task head, just classify a document with the label of nearby labeled embeddings. 
			- actually works BETTER than fine-tuning+task-head when ~50 labeled training pts per class
- pretraining
	- take documents, mask 15% of words, train a task-head which predicts over all ~30k vocabulary.
	- just throw away the task head, keep the (transformer+mlp) architecture
- fine-tuning
	- rule of thumb: (3-4 training epochs) + (~1k labeled training pts/label) → usually achieves ~90% accuracy for most tasks
	- model not good enough still?
		- more labeled data / clean up existing labeled data
			- data quality almost always the key to better performance
		- lower learning rate 
			- BERT highly sensitive to learning rate. catastrophic forgetting = overwriting pre-trained general language understanding
		- more epochs, larger batch sizes
		- switch base model (distillBERT → BERT base → BERT large → roBERTa)
		- additional pre-training on more documents from your domain
		- replace simple task head with
			- add dropout beforehand
			- replace with small MLP
- other models
	- DistillBERT = 40% smaller, 2x faster inference, 97% accuracy of BERT
	- RoBERTa = longer better pre-training. strictly superior to BERT
	- BigBird / Longformer = use to extend context window from 512 → 4096
